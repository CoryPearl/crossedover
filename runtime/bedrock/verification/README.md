These are **public verification keys**, not signing or content-decryption keys.
Both were read from Microsoft's unmodified `native/bin/xsapi.dll` in

Each blob is 539 bytes: a 24-byte BCRYPT_RSAKEY_BLOB header, three-byte
public exponent, and 512-byte public modulus. Their fingerprints match the
independent [xvdtool key inventory](https://github.com/emoose/xvdtool/blob/master/LibXboxOne/Keys/DurangoKeys.cs).
No private key or proprietary executable is included in this directory.

XVD signatures use RSA-PSS/SHA-256. A header signature alone does **not** verify
all package content: the authenticated root hash must anchor checks of every
hash-tree and data page before any game code is installed or executed. This
work is in development; it does not enable an unchecked HTTP fallback.

## Verification boundary

`package_integrity.rs` uses macOS Security.framework for RSA-PSS/SHA-256 and
CommonCrypto for page hashing. Production accepts only the two pinned public
keys above. It supports the reviewed fixed XVD layout, with 4 KiB or 12 KiB
signed headers, 4 KiB pages and 170 hash entries per tree page. Embedded,
resilient and dynamic layouts are currently rejected. The signed mutable-page
count is used only to skip an unused section, which the pinned parser never
reads. Its contents and unused header padding are not authenticated game data;
they never become files, executable code or parser input. Encrypted leaf
entries contain 20 digest bytes plus their authenticated encryption-unit value;
plaintext leaf and parent entries contain 24 digest bytes. The top page uses a
full 32-byte digest. The catalog size must match the complete layout exactly.

The helper downloads into a private temporary directory, verifies the signed
layout before accepting the body, then checks the complete tree and every data
page before any XVD, filesystem or game-file parser runs. Verified local bytes
are used for extraction. Microsoft ownership/content-license checks remain
required. All network candidates use this boundary, including HTTPS. An error
never falls back to unsigned parsing or partial extraction.

`fixtures/` contains only an owned public test key and six signed synthetic
headers, generated by `fixtures/generate.py`. Private fixture signing material
exists only in generator memory. The Rust tests reconstruct deterministic page
data and tree levels, verify single/multiple levels, skipped mutable padding and encrypted/plaintext
entry shapes, and reject changed signatures, headers, tree pages, plaintext
metadata, game data, truncation, extra bytes and unsupported layouts. Production
verification explicitly rejects these test signatures.

The full archive is removed after extraction or ordinary cancellation/failure.
The installed game retains only the metadata prefix needed by later account
license checks. This is package authenticity/integrity verification; it does
not claim protection from rollback to another legitimately signed package or
establish game compatibility.
